# 架构助手验收展示流程

本文档用于课堂答辩或项目验收展示，目标是在本地 Windows 环境中完整演示：

1. 构建前端
2. 启动四个微服务
3. 健康检查
4. 打开前端页面
5. 提交典型需求
6. 展示候选架构、拓扑图、决策溯源和报告
7. 可选运行批量测试

## 一键冒烟脚本

推荐先运行一键验收脚本，它会自动完成前置检查、必要时构建前端、启动服务、健康检查、首页检查、API 分析和清理：

```powershell
cd E:\workspace\UserRegister\arch-assistant
.\scripts\acceptance-demo-windows.ps1
```

CMD 入口：

```cmd
scripts\acceptance-demo-windows.cmd
```

常用参数：

```powershell
# 强制重新构建前端
.\scripts\acceptance-demo-windows.ps1 -ForceBuild

# 冒烟通过后保留四个服务，便于继续打开浏览器演示
.\scripts\acceptance-demo-windows.ps1 -KeepServices

# 冒烟通过后继续运行完整批量测试，耗时较长
.\scripts\acceptance-demo-windows.ps1 -RunBatch

# 自定义演示需求
.\scripts\acceptance-demo-windows.ps1 -Prompt "开发在线视频处理平台，用户上传视频后需要经过转码、加水印、生成缩略图、内容审核等一系列处理步骤。"
```

脚本输出和日志位置：

```text
logs\acceptance\
```

每次运行会生成类似：

```text
logs\acceptance\acceptance-result-YYYYMMDD-HHMMSS.json
```

## 手动展示步骤

### 1. 前置检查，约 1 分钟

```powershell
cd E:\workspace\UserRegister\arch-assistant
Test-Path .venv-win\Scripts\python.exe
Test-Path .env
Test-Path frontend\dist\index.html
```

三项都应输出 `True`。如果前端构建产物不存在：

```powershell
cd frontend
npm run build
cd ..
```

### 2. 启动服务，约 5-15 秒

PowerShell：

```powershell
.\scripts\start-local-windows.ps1
```

CMD：

```cmd
scripts\start-local-windows.cmd
```

服务分工：

```text
API Gateway            3000  浏览器入口、前端托管、API/SSE 转发
Orchestration Engine   8001  编排 Agent Runtime 和 LLM Router
LLM Router             8002  统一大模型调用入口
Agent Runtime          8003  三 Agent 推理、知识库、案例学习
```

### 3. 健康检查，约 10-20 秒

```powershell
Invoke-RestMethod http://127.0.0.1:8002/health
Invoke-RestMethod http://127.0.0.1:8003/health
Invoke-RestMethod http://127.0.0.1:8001/health
Invoke-RestMethod http://127.0.0.1:3000/health
```

期望四个接口都返回 `status: healthy`。

### 4. 打开前端，约 10 秒

浏览器访问：

```text
http://127.0.0.1:3000/
```

页面标题应为：

```text
Architecture Assistant - 软件架构风格智能助手
```

### 5. 典型需求演示，约 30-120 秒

推荐输入：

```text
开发银行核心交易系统，需要处理转账、存款、贷款等业务，对数据一致性和审计追踪有极高要求，支持日均百万笔交易。
```

讲解顺序：

1. 需求特征提取：并发、一致性、审计追踪、交易等关键约束。
2. 候选架构排序：首选通常应为 `CQRS (命令查询职责分离)`。
3. 质量属性雷达图：比较扩展性、性能、耦合、复杂度、部署弹性、可测试性。
4. 架构拓扑图：展示命令侧、写库、事件投影、查询侧、读库。
5. 决策溯源：解释哪些需求特征导致该架构推荐。
6. 专业评估报告：展示多维度对比、组合建议和风险提示。

### 6. API 冒烟展示，约 30-120 秒

```powershell
$payload = @{
  prompt = "开发银行核心交易系统，需要处理转账、存款、贷款等业务，对数据一致性和审计追踪有极高要求，支持日均百万笔交易。"
  session_id = "smoke_acceptance_demo"
} | ConvertTo-Json -Compress

Invoke-RestMethod `
  -Uri "http://127.0.0.1:3000/api/v1/analyze" `
  -Method Post `
  -Body $payload `
  -ContentType "application/json; charset=utf-8" `
  -TimeoutSec 180
```

验收重点：

```text
features    有结构化需求特征
candidates  有候选架构列表
topology    有节点和边
report      有评估报告
cached      表示是否命中缓存
```

### 7. 批量测试，约 10-60 分钟

完整批量测试依赖模型响应速度，现场展示可只说明脚本，必要时再运行：

```powershell
python run_tests.py
```

WSL/Linux：

```bash
bash run_tests.sh
```

输出文件：

```text
test_progress.json
test_results.json
```

### 8. 停止服务，约 10 秒

如果使用 `start-local-windows.ps1` 启动，可按端口停止：

```powershell
Get-NetTCPConnection -LocalPort 3000,8001,8002,8003 |
  Select-Object -ExpandProperty OwningProcess -Unique |
  ForEach-Object { Stop-Process -Id $_ -Force }
```

确认端口释放：

```powershell
Get-NetTCPConnection -LocalPort 3000,8001,8002,8003 -ErrorAction SilentlyContinue
```

没有输出即表示端口已释放。

## 推荐现场节奏

```text
第 1 分钟：介绍系统由 Vue 前端和 4 个 FastAPI 微服务组成
第 2-3 分钟：启动服务并健康检查
第 4 分钟：打开前端，说明输入区和结果区
第 5-8 分钟：提交银行核心交易需求，展示 CQRS 推荐
第 9-12 分钟：讲解特征、候选、雷达图、拓扑、溯源和报告
第 13-15 分钟：展示 API 冒烟脚本和批量测试脚本
```

最稳妥的现场方案是：前端演示 + API 冒烟；批量测试作为可运行验收脚本展示，除非现场明确要求跑完整套。
